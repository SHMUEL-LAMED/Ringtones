# ראש בראש — מצעד המוזיקה הגדול

אתר התוכנית "ראש בראש": התוכנית האחרונה בדף הבית, ארכיון מלא של כל התוכניות,
רשימת השירים של כל תוכנית — כשכל שיר מקושר לרגע שבו הושמע בהקלטה — ואזור אישי לכל מאזין.

האתר סטטי (GitHub Pages), בעברית מימין לשמאל, ובנוי על מערכת העיצוב "אולפן לילה":
רקע חצות עם זוהר נע וגרעיניות עדינה, זהב חם, טיפוגרפיה ענקית (Karantina) וגוף ברור (Heebo),
כרטיסי זכוכית כהים, עטיפה צבעונית שנגזרת מהעונה ומהמזהה של כל תוכנית, תקליט שמסתובב
בזמן ניגון, אקולייזר חי בגיבור, סרט נע של התוכניות, מספרים רצים, גילוי בגלילה, מעבר רך
בין דפים (View Transitions) ואור שעוקב אחרי הסמן. כל התנועה כבויה תחת
`prefers-reduced-motion`.

## מה יש באתר

| דף | מה יש בו |
| --- | --- |
| `index.html` | הגיבור עם המדליון, התוכנית המומלצת/האחרונה עם נגן ורשימת שירים, "מאיפה שעצרתם", תוכניות אחרונות, מספרים |
| `archive.html` | כל התוכניות: חיפוש (גם בשירים ובזמרים), סינון לפי עונה / עם הקלטה / לאחר כך, מיון, תצוגת רשת / רשימה / לפי עונות. חיפוש שיר מחזיר **את הרגע** שבו הושמע בכל תוכנית |
| `episode.html?ep=…` | דף תוכנית: הקלטה, תיאור, רשימת השירים עם קפיצה לרגע, קישור לכל רגע (`&t=שניות`), הורדה, שיתוף, קודמת/הבאה, עוד מאותה תקופה |
| `me.html` | האזור האישי (ראו למטה) |
| `admin.html` | אזור הניהול (ראו למטה) |

### הנגן הקבוע

נגן אחד לכל האתר, שנשאר פתוח במעבר בין דפים. **ההקלטות מנוגנות בנגן של האתר** — גם
כשהקובץ שמור בדרייב. אין הפניה החוצה, אין iframe, ושום דבר מהממשק של ספק האחסון לא מוצג
לציבור; קישורי הדרייב שבנתונים מוסתרים מהדפים הציבוריים (`RoshUI.publicLinks`).

איך זה עובד: גוגל מגיש קובץ דרייב משותף כאודיו רגיל (Range, CORS) לשרתים, אבל עונה 403 לכל
בקשת דפדפן חוצת־אתרים (`Sec-Fetch-Site: cross-site`) — כך שאי אפשר לטעון אותו ישירות ב־`<audio>`
מאתר אחר. לכן `RoshUI.streamCandidates(ep)` מחזיר כתובות לפי עדיפות:

1. `{apiBase}/api/program/stream/{מזהה}` — ה־Worker של אתר הסקר מזרים את הקובץ ומעביר Range
   (הקוד ב־`worker/program-api.ts` במאגר `rosh-berosh`).
2. הכתובת הישירה (`drive.usercontent.google.com/download?…`) — גיבוי לדפדפנים שאינם שולחים
   את הכותרת, וגם כתובת ההורדה (`RoshUI.downloadUrl`; ניווט/הורדה לא נחסמים).

הנגן עובר אוטומטית למקור הבא כשמקור נכשל, ואם כולם נכשלו מציע "ניסיון חוזר" והורדה.
כל תוכנית מקבלת שדה מחושב `ep.stream` (הכתובת הראשונה; לא נכנס ל־JSON שמתפרסם).

- תקליט מסתובב ואקולייזר חי בזמן ניגון (`body.is-playing`)

- פס התקדמות **מחולק לשירים** לפי רשימת השירים; ריחוף מציג את שם השיר בכל נקודה
- "מתנגן עכשיו" מתעדכן לפי הזמן, וגם על מסך הנעילה (Media Session)
- ממשיך מאיפה שעצרתם (נשמר במכשיר), עם אפשרות "מההתחלה"
- מהירות 0.75×–2×, טיימר כיבוי (בזמן או בסוף השיר), השתקה, שיתוף הרגע הנוכחי
- קיצורי מקלדת: רווח ניגון/השהיה, חצים ±15 שניות, Shift+חץ לשיר הבא/הקודם, 0–9 קפיצה לאחוז, M השתקה, +/− מהירות, R תוכנית אקראית, `?` לעזרה
- "הפתיעו אותי" — תוכנית אקראית עם הקלטה

## האזור האישי

`me.html` — כל אחד מתחבר עם Google (אותו חלון כניסה של אתר הסקר, `/api/program/login`) ורואה:
ממשיכים מאיפה שעצרתם, "לאחר כך", היסטוריית האזנה, שעות האזנה והעדפות (מהירות קבועה).
הנתונים האישיים נשמרים במכשיר (localStorage). בכותרת האתר מופיע תמיד קישור לאזור האישי
(עם השם כשמחוברים).

**כפתור "ניהול" מוצג רק למי שמחובר בחשבון שמוגדר כמנהל באתר הסקר** (`user.isAdmin`) — בכותרת
ובאזור האישי ("מעבר לניהול"). מי שמחובר ואינו מנהל רואה את האזור האישי בלבד; `admin.html`
נשאר נעול לו. הסשן (`rosh:cf:session`) נשמר לכל משתמש; `isAdmin` מתרענן מול `/api/program/me`.

> ההתחברות של מאזינים שאינם מנהלים וההזרמה דרך ה־Worker דורשות את גרסת ה־Worker שמנפיקה
> סשן לכל חשבון Google (`isAdmin:false` למי שאינו מנהל) וכוללת את `/api/program/stream` —
> ראו את ה־PR המקביל במאגר `rosh-berosh`. עד שהוא נפרס: הכניסה פתוחה למנהלים בלבד, והנגן
> נופל לכתובת הישירה ומציע הורדה.

## אזור הניהול

`admin.html` — עובדים על **טיוטה** שנשמרת בדפדפן (Ctrl+S). האתר במכשיר הזה מציג את הטיוטה,
כך שאפשר לבדוק הכול לפני שמפרסמים. "פרסום" מעביר את הטיוטה למקור.

- יצירה, שכפול, מחיקה (עם ביטול), הסתרה/הצגה, סימון "תוכנית מומלצת"
- כל השדות: כותרת, מספר, תאריך, עונה, כתובת (slug אוטומטי), תיאור, תגיות, אורחים, תמונה, הקלטה, אורך (נקרא מהקובץ), קישורים
- **עורך רשימת השירים**: נגן תצוגה מקדימה (עובד גם על הקלטות שבדרייב, דרך אותה הזרמה ישירה), כפתור "סמן" שמעתיק את הזמן מהנגן לשיר, "+ שיר מהנקודה בנגן",
  גרירה לסידור, מיון לפי זמן, ו**הדבקת רשימה** שלמה (שורה לשיר, עם או בלי זמנים)
- ניהול עונות, עריכת JSON מלאה עם אימות, ייבוא וייצוא קובץ
- **טעינה מהמאגר**: טוען לטיוטה את `data/episodes.json` שמתפרסם עם האתר. כך עדכון שנעשה
  במאגר (תיאורים, עונות, תאריכים) מגיע למקור הנתונים בלחיצה על "פרסום"
- תצוגה מקדימה חיה של הכרטיס

### מקור הנתונים

`data/site.json` → `storage.provider` קובע מאיפה האתר קורא:

**`"cloudflare"` (מוגדר כרגע)** — התוכניות נשמרות באותו Cloudflare D1 של אתר הסקר,
והקלטות ותמונות חדשות נשמרות באותו R2. הציבור קורא רק תוכניות מוצגות; כתיבה אפשרית רק
למנהלים שכבר מוגדרים באזור **הרשאות** של אתר הסקר.

**מי שמנהל את אתר הסקר מנהל גם כאן.** באזור הניהול לוחצים **התחברות לניהול**: נפתח חלון
קטן בכתובת אתר הסקר (`/api/program/login`). מי שכבר מחובר שם כמנהל מקבל מיד סשן מנהל
לאתר התוכניות ל־30 יום, בלי כניסה נוספת. מי שאינו מחובר שם מתחבר בחלון עם Google, ואותה
רשימת מנהלים מכריעה. הוספה או הסרה של מנהל מתבצעת רק בלשונית **הרשאות** של אתר הסקר
ומשפיעה מיד גם על אתר התוכניות — אין רשימת מנהלים נפרדת, וגם סשן קיים נבדק מול הרשימה
בכל בקשה.

- כתובת ה־API מוגדרת ב־`data/site.json` תחת `storage.cloudflare.apiBase`.
- הטבלאות `program_episodes` ו־`program_settings` נוצרות אוטומטית ב־D1 של אתר הסקר.
- אם Cloudflare אינו זמין, האתר נופל חזרה ל־`data/episodes.json` לקריאה בלבד.

**`"json"`** — בלי שרת בכלל. האתר קורא את `data/episodes.json` מהמאגר, ו"פרסום" באזור הניהול
מוריד קובץ מעודכן שמעלים למאגר.

### מבנה תוכנית (`data/episodes.json`)

```json
{
  "id": "2026-09-19",
  "slug": "2026-09-19",
  "number": 38,
  "season": "2026",
  "title": "שירי הסתיו",
  "date": "2026-09-19",
  "description": "מה היה בתוכנית…",
  "cover": "https://…/cover.jpg",
  "audio": "https://…/episode.mp3",
  "duration": 3480,
  "tags": ["מצעד"],
  "guests": [],
  "featured": true,
  "visible": true,
  "tracks": [
    { "at": 0, "title": "פתיחה", "artist": "", "note": "" },
    { "at": 185, "title": "שם השיר", "artist": "שם הזמר", "note": "" }
  ],
  "links": [{ "label": "הפלייליסט", "url": "https://…" }]
}
```

`at` הוא זמן בשניות מתחילת ההקלטה. `seasons` הוא מערך של `{ id, title, year, note }`;
`note` מוצג בארכיון בתצוגה "לפי עונות" מתחת לכותרת העונה.

### העונות משקפות את תיקיות ארכיון התוכנית

העונות מוגדרות לפי מבנה התיקיות של ארכיון התוכנית (הדרייב המשותף של "ראש בראש"), ובאותו סדר:

| עונה | תיקייה | מה בפנים |
| --- | --- | --- |
| `slater` | `01 פרקים מלאים / 01 בהגשת קובי בלום וירמי סלייטר` | פרקים 80 ואילך |
| `levi` | `01 פרקים מלאים / 02 בהגשת מיכאל לוי וקובי בלום` | פרקים 55–78 |

| `trio` | `01 פרקים מלאים / 04 גרסת השלישייה` | פרק 79 |
| `sets` | `02 סטים` | הסטים המוזיקליים |

התיאורים של התוכניות הם הטקסטים שנשלחו בתפוצת המייל של התוכנית עם כל פרק (בלי כותרות
העזר וההערות הטכניות של התפוצה), וההערות של העונות לקוחות מההודעות של צוות התוכנית.
לתוכניות שלא נשלח להן תיאור (פרקים 55–58, 60, 64, שני סטים והארכיון) התאריך הוא מועד
ההעלאה לארכיון התוכנית.

## הרצה מקומית ובדיקה

```bash
node tests/catalog.cjs         # הקטלוג, כתובות ההזרמה, הסתרת קישורי האחסון, העלאות
npx http-server -p 4180 .      # בחלון אחד
node tests/browser-smoke.mjs   # בחלון שני (דורש Playwright: npm i -g playwright; OFFLINE=1 מדלג על ההזרמה)
```

הבדיקה עוברת בדפדפן אמיתי על הקטלוג האמיתי: הנגן נפתח ומזרים את ההקלטה ישירות (כולל קפיצה
באמצע), המיקום נשמר במעבר לארכיון, סינון וחיפוש, דף תוכנית בלי נגן חיצוני, האזור האישי,
וכפתור הניהול שמופיע רק לסשן של מנהל.

## העברת ההקלטות לאחסון של האתר

ההקלטות עצמן שמורות היום בדרייב של התוכנית, והנגן מזרים אותן דרך ה־Worker
(`/api/program/stream/<id>`). GitHub Pages לא יכול לאחסן אותן: כל ההקלטות יחד שוקלות כ־8GB,
יש קבצים של 200–300MB, ול־GitHub יש מגבלה של 100MB לקובץ ו־1GB למאגר.

הדרך לקבצים "ממש על האתר" היא ה־R2 של Cloudflare — אותו אחסון שאליו כבר עולות הקלטות
חדשות מאזור הניהול (`/api/program/upload`). כשקובץ שמור ב־R2, השדה `audio` של התוכנית מקבל
את כתובת הקובץ הישירה, והנגן מנגן אותו בלי שום תלות בדרייב (`RoshUI.streamCandidates`
מעדיף קובץ ישיר על פני הזרמה). מה נדרש כדי להעביר את הארכיון הקיים:

1. נקודת קצה ב־Worker (במאגר `rosh-berosh`) שמעתיקה קובץ דרייב ל־R2 בצד השרת
   (`POST /api/program/import { episode, driveId }`), בהעלאה מרובת חלקים — הדפדפן לא צריך
   להוריד ולהעלות 300MB.
2. כפתור "העתקה לאחסון האתר" בעורך התוכנית באזור הניהול, שקורא לנקודה הזו ומעדכן את `audio`.
3. הרצה אחת על כל הקטלוג (86 קבצים). הזרמה מהדרייב נשארת כגיבוי לכל תוכנית שעוד לא הועתקה.

## פריסה

כל דחיפה ל־`main` מפרסמת את המאגר כמו שהוא ל־GitHub Pages (`.github/workflows/pages.yml`).
