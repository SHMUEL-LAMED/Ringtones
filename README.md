# ראש בראש — מצעד המוזיקה הגדול

אתר התוכנית "ראש בראש": התוכנית האחרונה בדף הבית, ארכיון מלא של כל התוכניות עם האזנה
ישירה באתר, ואזור אישי לכל מאזין. באתר יש תוכניות בלבד — בלי רשימות שירים וזמרים (אלה באתר הסקר).

האתר סטטי (GitHub Pages), בעברית מימין לשמאל, ובנוי על מערכת העיצוב "אולפן לילה":
רקע חצות עם זוהר נע וגרעיניות עדינה, זהב חם, טיפוגרפיה ענקית (Karantina) וגוף ברור (Heebo),
כרטיסי זכוכית כהים, עטיפה צבעונית שנגזרת מהעונה ומהמזהה של כל תוכנית, תקליט שמסתובב
בזמן ניגון, אקולייזר חי בגיבור, סרט נע של התוכניות, מספרים רצים, גילוי בגלילה, מעבר רך
בין דפים (View Transitions) ואור שעוקב אחרי הסמן. כל התנועה כבויה תחת
`prefers-reduced-motion`.

## מה יש באתר

| דף | מה יש בו |
| --- | --- |
| `index.html` | הגיבור עם המדליון, התוכנית המומלצת/האחרונה עם נגן, "מאיפה שעצרתם", תוכניות אחרונות, מספרים, הצטרפות לתפוצה ו"כתבו לנו" |
| `archive.html` | כל התוכניות: חיפוש, סינון לפי עונה / עם הקלטה / לאחר כך, מיון, תצוגת רשת / רשימה / לפי עונות |
| `episode.html?ep=…` | דף תוכנית: הקלטה, תיאור, קישור לכל רגע (`&t=שניות`), הורדה, שיתוף, תגובה למגישים, קודמת/הבאה, עוד מאותה תקופה |
| `episodes/<slug>.html` | אותו דף תוכנית בכתובת קבועה לגוגל: נבנה בפריסה עם כותרת, תיאור, תגיות שיתוף ונתונים מובנים, והתוכן כבר בתוך ה־HTML (ראו "פריסה") |
| `me.html` | האזור האישי (ראו למטה) |
| `updates.html` | דף העדכונים שמנהל כותב באזור הניהול |
| `negishut.html` | הצהרת הנגישות |
| `offline.html` | מה שמוצג כשאין חיבור לאינטרנט |
| `admin.html` | אזור הניהול (ראו למטה) |

### ניווט בלי טעינה מחדש

לחיצה על קישור פנימי מחליפה רק את תוכן הדף (`assets/js/router.js`), כך שהנגן ממשיך לנגן
בלי הפסקה בזמן שעוברים בין הבית, הארכיון, דפי התוכניות והאזור האישי. הכתובת, "אחורה" ו"קדימה",
הכותרת והשיתוף עובדים כרגיל. הניהול, הורדות וקישורים לחלון חדש נטענים כרגיל. כל דף רושם את
המאזינים שלו עם `RoshApp.signal`, והם מוסרים במעבר לדף אחר.

### הנגן הקבוע

נגן אחד לכל האתר, שנשאר פתוח במעבר בין דפים. **ההקלטות מנוגנות בנגן של האתר** — גם
כשהקובץ שמור בדרייב. אין הפניה החוצה, אין iframe, ושום דבר מהממשק של ספק האחסון לא מוצג
לציבור; קישורי הדרייב שבנתונים מוסתרים מהדפים הציבוריים (`RoshUI.publicLinks`).

איך זה עובד: גוגל מגיש קובץ דרייב משותף כאודיו רגיל (Range, CORS) לשרתים, אבל עונה 403 לכל
בקשת דפדפן חוצת־אתרים (`Sec-Fetch-Site: cross-site`) — כך שאי אפשר לטעון אותו ישירות ב־`<audio>`
מאתר אחר. לכן `RoshUI.streamCandidates(ep)` מחזיר כתובות לפי עדיפות:

1. `{apiBase}/api/program/stream/{מזהה}` — ה־Worker של אתר הסקר מזרים את הקובץ ומעביר Range
   (הקוד ב־`worker/program-api.ts` במאגר `rosh-berosh`).
2. הכתובת הישירה (`drive.usercontent.google.com/download?…`) — גיבוי לדפדפנים שאינם שולחים
   את הכותרת, וגם כתובת ההורדה (`RoshUI.downloadUrl`; ניווט/הורדה לא נחסמים).

הנגן עובר אוטומטית למקור הבא כשמקור נכשל, ואם כולם נכשלו מציע "ניסיון חוזר" והורדה.
כל תוכנית מקבלת שדה מחושב `ep.stream` (הכתובת הראשונה; לא נכנס ל־JSON שמתפרסם).

- תקליט מסתובב ואקולייזר חי בזמן ניגון (`body.is-playing`)
- **תור האזנה**: "+ לתור" בכל תוכנית; כשתוכנית נגמרת, הבאה בתור מתחילה לבד. בלי תור — מוצע
  לעבור ל"תוכנית הבאה" (החדשה יותר, אותו כיוון כמו ▸▸)
- **הורדה** מהאחסון של האתר, בשם התוכנית (`/api/program/download/<id>`), לא מהדרייב
- **שיתוף**: הקישור (`/p/<slug>` בשרת) מציג בוואטסאפ את שם התוכנית והתמונה, ומעביר לדף התוכנית
- פס התקדמות עם ריחוף שמציג את הזמן; שם התוכנית גם על מסך הנעילה (Media Session)
- ממשיך מאיפה שעצרתם (נשמר במכשיר), עם אפשרות "מההתחלה"
- מהירות 0.5×–2× (אותה רשימה בנגן, במקלדת ובאזור האישי), שיתוף הרגע הנוכחי
- קיצורי מקלדת: רווח ניגון/השהיה, חצים ±15 שניות, Shift+חץ לתוכנית הבאה/הקודמת, 0–9 קפיצה לאחוז, +/− מהירות, R תוכנית אקראית, `?` לעזרה
- "הפתיעו אותי" — תוכנית אקראית עם הקלטה

## האזור האישי

`me.html` — כל אחד מתחבר עם Google ישירות מהדף (כפתור Google; האישור נשלח ל־`/api/program/auth/google`) ורואה:
ממשיכים מאיפה שעצרתם, התור, "לאחר כך", היסטוריית האזנה, זמן האזנה אמיתי, תוכניות ששמע עד הסוף,
והעדפות (מהירות, מצב בהיר/כהה, אנימציות, התראות לטלפון).

**הנתונים האישיים נשמרים רק בחשבון Google — שום דבר אישי לא נשמר במכשיר.** הם נטענים מ־
`/api/program/userdata` במקביל לקטלוג, ונשמרים בו אחרי כל שינוי (`RoshStore.me`), ולכן זהים בכל
מכשיר. בלי התחברות הנתונים חיים רק בזיכרון של הביקור, ומצטרפים לחשבון ברגע שמתחברים. נתונים
ישנים שנשמרו פעם במכשיר עוברים לחשבון בהתחברות הראשונה ונמחקים מהמכשיר. במכשיר נשאר רק הסשן
עצמו. בכותרת האתר מופיע תמיד קישור לאזור האישי (עם השם כשמחוברים), וכפתור מצב בהיר/כהה.

**"אהבתי"** (`/api/program/likes`) — לב בכל תוכנית (דורש התחברות). המאזין רואה רק את הסימון
שלו; כמה אהבו כל תוכנית מוצג למנהלים בלבד (בחלק "מאזינים" בניהול). "תוכניות שאהבתי" באזור האישי.

**התראות לטלפון** (Web Push) — מפעילים באזור האישי. בפרסום תוכנית חדשה נשלחת התראה (אפשר לכבות
בכפתור הפרסום), תוכנית מתוזמנת שולחת כשהיא עולה, ומנהל יכול לשלוח הודעה משלו מחלק "מאזינים".
באייפון ההתראות עובדות רק כשהאתר מותקן למסך הבית.

**כפתור "ניהול" מוצג רק למי שמחובר בחשבון שמוגדר כמנהל באתר הסקר** (`user.isAdmin`) — בכותרת
ובאזור האישי ("מעבר לניהול"). מי שמחובר ואינו מנהל רואה את האזור האישי בלבד; `admin.html`
נשאר נעול לו. הסשן (`rosh:cf:session`) נשמר לכל משתמש; `isAdmin` מתרענן מול `/api/program/me`.

> ההתחברות של מאזינים שאינם מנהלים וההזרמה דרך ה־Worker דורשות את גרסת ה־Worker שמנפיקה
> סשן לכל חשבון Google (`isAdmin:false` למי שאינו מנהל) וכוללת את `/api/program/stream` —
> ראו את ה־PR המקביל במאגר `rosh-berosh`. עד שהוא נפרס: הכניסה פתוחה למנהלים בלבד, והנגן
> נופל לכתובת הישירה ומציע הורדה.

## אזור הניהול

`admin.html` — ארבעה חלקים, בשפה פשוטה, בלי קודים ובלי מזהים. כל שינוי נשמר מיד **בטיוטה
המשותפת בשרת** (`/api/program/draft`, לפי חשבון ה־Google של המנהל), כך שאפשר להתחיל במחשב
ולהמשיך בטלפון. **שום טיוטה לא נשמרת במכשיר**: הדף טוען בכניסה את מה שמפורסם ואת הטיוטה
המשותפת, העריכה נשארת בזיכרון, ונשמרת לשרת כשנייה וחצי אחרי כל שינוי (וגם כשסוגרים את הדף או
עוברים לאפליקציה אחרת). אם השרת לא זמין מופיעה אזהרה — "השינויים לא נשמרים לשרת — אל תסגרו את
הדף" — והשמירה ממשיכה לבד כשהחיבור חוזר. אם מנהל אחר שמר בינתיים טיוטה חדשה יותר, שום דבר לא
נדרס בשקט: הדף שואל אם לטעון את הטיוטה שלו או להמשיך עם שלכם ולדרוס. "פרסום לאתר" מעביר את
הטיוטה לכולם ומוחק אותה מהשרת; "ביטול כל השינויים" מוחק אותה לכל המנהלים. עד הפרסום רק המנהלים
רואים את הטיוטה. בכניסה הראשונה נפתח מדריך קצר (וכפתור `?` תמיד זמין).

1. **תוכניות** — רשימה עם חיפוש וסינון, וטופס לכל תוכנית: שם, תאריך, מספר, עונה, אורחים,
   תיאור, הקלטה (העלאה בכל גודל עד 1GB — קובץ גדול עולה בחלקים של 20MB; או קישור; האורך נקרא
   מהקובץ), תמונה (העלאה, קישור, או **יצירת תמונה אוטומטית** ריבועית בסגנון האתר, שהטקסט שלה
   נשאר גלוי גם בכרטיסים), **תיאור וסיכום ב־AI** מתמלול ההקלטה (התמלול גלוי למנהלים בלבד), מוצגת/מוסתרת, מומלצת בדף הבית, **פרסום מתוזמן**
   (התוכנית עולה לאתר במועד שנקבע), טקסט מוכן לוואטסאפ, שכפול, מחיקה עם ביטול, **גרסאות קודמות**
   של התוכנית, ותצוגה מקדימה של הכרטיס. **בחירה מרובה**: הצגה, הסתרה, שיוך לעונה ומחיקה של כמה
   תוכניות יחד.
2. **האתר** — **הודעה בראש כל הדפים** (עם קישור ותאריך סיום), **דף עדכונים** (`updates.html`,
   מופיע בתפריט כשיש עדכונים) ועונות לסידור הארכיון.
3. **מאזינים** — **סטטיסטיקות האזנה** אנונימיות (האזנות, מאזינים, שעות, גרף ימים, התוכניות
   הכי נשמעות, טלפון/מחשב, **מאיפה הגיעו** — וואטסאפ/גוגל/ישיר, **באיזו שעה מאזינים**, **הכי
   אהובות**, ו**עד איפה מאזינים** בכל תוכנית), **שליחת התראה** לכל המאזינים, **הודעות מהמאזינים** (מ"כתבו לנו" בדף הבית ובדפי התוכניות) ומספר
   הנרשמים לרשימת התפוצה.
4. **פרסום** — מה השתנה, **בדיקת תקינות** מקובצת (כמה תוכניות בלי אורך / תמונה / תיאור, עם
   תיקון לכולן בלחיצה: מילוי האורך מהקבצים, יצירת תמונות, תיאורים מהתמלול; **כפילויות**,
   **בדיקת ההקלטות**, **בדיקת תמונות וקישורים**), **הגנה מדריסה** (אם מנהל אחר פרסם מאז שהתחלתם
   לערוך, הפרסום נעצר ושואל), כפתור הפרסום, **גרסאות קודמות** (כל פרסום נשמר אוטומטית; שחזור בלחיצה)
   וכלים מתקדמים: **קישור לתצוגה מקדימה** של הטיוטה, קובץ גיבוי ושחזור ממנו, העברת ההקלטות
   מהדרייב לאתר, **ניהול המנהלים** (אותה רשימה של אתר הסקר) והחשבון.

הכניסה לניהול ולאזור האישי היא **ישירות עם Google מתוך האתר** (כפתור Google בדף עצמו, בלי דף
ביניים). הקישור "כניסה דרך אתר הסקר" נשאר כגיבוי. כדי שהכפתור יעבוד, כתובת האתר
(`https://shmuel-lamed.github.io`) צריכה להופיע ב־Authorized JavaScript origins של ה־OAuth client
בגוגל.

**רשימת התפוצה** — בדף הבית ובאזור האישי: מתחברים עם Google וההצטרפות היא בלחיצה אחת. הכתובת
נלקחת מהחשבון המחובר ונשמרת באותה רשימה של אתר הסקר (`subscribers`), שמנוהלת שם.

### דף ניהול אחד עם אתר הסקר

הסקר ואתר התוכניות מנוהלים **באותו דף** — דף הניהול של אתר הסקר (`/admin` ב־Worker). בתפריט הצד
שלו יש חלק **"אתר התוכניות"** עם ארבעת החלקים של הניהול הזה (תוכניות, הודעה ועדכונים, מאזינים,
פרסום התוכניות), לצד הסקרים, האלבומים, התוצאות וכל השאר. הניהול כאן נטען שם בתוך הדף
(`admin.html?handoff=…&embed=1`), בלי תפריט לשוניות משלו: תפריט הצד בוחר את החלק (`postMessage`).

- **הכתובת `admin.html` מעבירה לדף המשותף** — לאותו חלק ובאותו חשבון, בלי כניסה נוספת (קוד מעבר
  חד־פעמי). `admin.html?standalone=1` משאיר את הניהול כאן, לבדיקות.
- **כניסה ויציאה אחת** — מתחברים פעם אחת, באתר הסקר או כאן, ומחוברים בשניהם: מי שמחובר באתר הסקר
  מחובר כאן אוטומטית (בדיקה רגעית ברקע, לכל היותר פעם בשש שעות), וכניסה כאן מחברת גם את אתר הסקר.
  התנתקות מנתקת משניהם.
- **הודעה משותפת** — בהודעה מסמנים איפה להציג: באתר התוכניות, באתר הסקר או בשניהם.
- **"הצביעו עכשיו"** — כשההצבעה במצעד פתוחה (`settings.survey.open` בקטלוג), פס בראש כל הדפים.
- **תוכנית מקושרת למצעד** — שדה `surveyId`; דף התוכנית מציג קישור להצבעה כשהמצעד הזה פתוח.
- **מנהלים וגיבוי** — אותה רשימת מנהלים, וגיבוי אחד לשני האתרים בלשונית "ארכיון וגיבויים".

### מקור הנתונים

`data/site.json` → `storage.provider` קובע מאיפה האתר קורא:

**`"cloudflare"` (מוגדר כרגע)** — התוכניות נשמרות באותו Cloudflare D1 של אתר הסקר,
והקלטות ותמונות חדשות נשמרות באותו R2. הציבור קורא רק תוכניות מוצגות; כתיבה אפשרית רק
למנהלים שכבר מוגדרים באזור **הרשאות** של אתר הסקר.

**מי שמנהל את אתר הסקר מנהל גם כאן.** באזור הניהול נכנסים עם כפתור Google שבדף עצמו ומקבלים
סשן ל־30 יום; אותה רשימת מנהלים מכריעה. הקישור "כניסה דרך אתר הסקר" פותח את חלון הכניסה הישן
(`/api/program/login`) למי שכבר מחובר שם. הוספה או הסרה של מנהל מתבצעת רק בלשונית **הרשאות** של אתר הסקר
ומשפיעה מיד גם על אתר התוכניות — אין רשימת מנהלים נפרדת, וגם סשן קיים נבדק מול הרשימה
בכל בקשה.

- כתובת ה־API מוגדרת ב־`data/site.json` תחת `storage.cloudflare.apiBase`.
- הטבלאות `program_episodes` ו־`program_settings` נוצרות אוטומטית ב־D1 של אתר הסקר.
- אם Cloudflare אינו זמין, האתר נופל חזרה ל־`data/episodes.json` לקריאה בלבד. הפריסה מרעננת את
  העותק הזה מהקטלוג החי (ראו "פריסה"), כך שהוא תמיד כמו האתר ביום הפריסה האחרונה. שרת שרק
  מתעכב (יותר מ־8 שניות, למשל מופע חדש של ה־Worker שמתעורר) אינו תקלה: העותק מוצג בלי הודעה.
  ההודעה "החיבור למקור הנתונים נכשל" מופיעה רק כשהשרת עונה בשגיאה או לא נגיש.

**`"json"`** — בלי שרת בכלל. האתר קורא את `data/episodes.json` מהמאגר, ו"פרסום" באזור הניהול
מוריד קובץ מעודכן שמעלים למאגר.

### מבנה תוכנית (`data/episodes.json`)

```json
{
  "id": "2026-09-19",
  "slug": "2026-09-19",
  "number": 38,
  "season": "2026",
  "title": "שירי הסתיו",
  "date": "2026-09-19",
  "description": "מה היה בתוכנית…",
  "cover": "https://…/cover.jpg",
  "audio": "https://…/episode.mp3",
  "duration": 3480,
  "tags": ["מצעד"],
  "guests": [],
  "featured": true,
  "visible": true,
  "publishAt": "",
  "links": [{ "label": "הפלייליסט", "url": "https://…" }]
}
```

`publishAt` (לא חובה, `"2026-10-01T20:00"`) הוא מועד פרסום מתוזמן. `seasons` הוא מערך של `{ id, title, year, note }`.
שדה `tracks` ישן נשמר אם קיים, אבל האתר לא מציג אותו.

assets/js/theme.js       מצב בהיר/כהה, הפסקת אנימציות, מצב קל לטלפונים חלשים (לפי קצב פריימים שנמדד בפועל)

assets/js/offline.js     "ניסיון חוזר" בדף offline.html

אין תהליך בנייה ואין תלויות. עורכים קובץ, מרעננים. (רק מפת האתר ודפי `episodes/` נבנים בפריסה.)

**מדיניות אבטחה (CSP):** בראש כל דף יש `<meta http-equiv="Content-Security-Policy">` — סקריפטים רק מהאתר עצמו
(וכפתור Google), חיבורים רק לאתר, ל־Worker ולגוגל. לכן אין בדפים `<script>` בתוך ה־HTML ואין
`onclick="…"` בתבניות: כל קוד בקובץ `.js` ומאזינים עם `addEventListener`. כתובת חיצונית חדשה
(API, סקריפט) צריכה להיכנס למדיניות בכל הדפים.

## הרצה מקומית ובדיקה

```bash
node tests/catalog.cjs         # הקטלוג, כתובות ההזרמה, הסתרת קישורי האחסון, העלאות
npx http-server -p 4180 .      # בחלון אחד
node tests/browser-smoke.mjs   # בחלון שני (דורש Playwright: npm i -g playwright; OFFLINE=1 מדלג על ההזרמה)
node tests/admin-smoke.mjs     # אזור הניהול, הפרסום והאתר אחריו — מול Worker מדומה
```

הבדיקה עוברת בדפדפן אמיתי על הקטלוג האמיתי: הנגן נפתח ומזרים את ההקלטה ישירות (כולל קפיצה
באמצע), המיקום נשמר במעבר לארכיון, סינון וחיפוש, דף תוכנית בלי נגן חיצוני, האזור האישי,
וכפתור הניהול שמופיע רק לסשן של מנהל.

הבדיקות רצות אוטומטית ב־GitHub על כל PR (`.github/workflows/tests.yml`).

## פריסה

כל דחיפה ל־`main` מריצה את הבדיקות, ורק אם עברו — מרעננת את העותק השמור (`data/episodes.json`), בונה את
מפת האתר ואת דפי התוכניות הסטטיים מהקטלוג החי ומפרסמת ל־GitHub Pages (`.github/workflows/pages.yml`). הפריסה רצה גם פעם ביום, כדי שתוכניות חדשות
(ותוכניות מתוזמנות שהגיע זמנן, לפי שעון ישראל) ייכנסו למפת האתר ויקבלו דף.

`scripts/build-episode-pages.mjs` מעתיק את `episode.html` לכל תוכנית מוצגת אל `episodes/<slug>.html`, עם
`<base href="../">` ראשון ב־`<head>` (כך שכל הכתובות היחסיות נשארות נכונות), כותרת, תיאור, canonical,
Open Graph/Twitter, JSON-LD (`RadioEpisode`), `data-ep` על `<body>` והתוכן עצמו בתוך `<article id="episode">`;
`episode.js` מצייר אותו מחדש עם הנגן. מפת האתר מפנה לדפים האלה. להרצה מקומית:
`node scripts/build-sitemap.mjs && node scripts/build-episode-pages.mjs` (התיקייה `episodes/` ב־`.gitignore`).

**עדכון גרסה:** מי שמשנה קבצים של המעטפת מעלה את `VERSION` ב־`sw.js`; הגרסה החדשה נכנסת לתוקף בדפים
פתוחים, ואז מוצג הפס "האתר עודכן — לחצו לרענון" (לא בזמן ניגון). לחיצה על התראה פותחת את התוכנית בחלון
הפתוח בלי טעינה מחדש, כך שהנגן ממשיך לנגן.
